## 1. What this is — and is not (GR-6)

This document defines how SpanSight computes **condition-rating transition frequencies**: how often bridges in a cohort moved from one published NBI condition rating to another between consecutive annual publications, 1992–2025.

Everything produced under this methodology is a **descriptive statistic of published federal inspection data at cohort level**. It is:

- **not a prediction** of what will happen to any structure, cohort, or network;
- **not an assessment** of any individual structure — no per-structure deterioration view exists anywhere in the product;
- **not engineering judgment** and not a substitute for inspection, load rating, or asset-management analysis.

FR-1.3 is titled "Deterioration patterns (Markov-chain baseline)" in the SRS, and a row-conditional
transition table *is* a Markov transition matrix — so the tension is worth naming rather than leaving a
reader to find it. What is computed here is only the empirical transition table. No chain is iterated,
no steady state is solved, no future year is projected; doing any of that would be a prediction and is
out of scope under GR-6.

The implementation must render this framing (§7) adjacent to every matrix or rate it displays.

## 2. Source data and population

- **Input:** the normalized vintage Parquet catalog (`tools/vintages/`, FR-1.1) — FHWA's *highway-bridges-only national single-file* exports, 1992–2025 (34 vintages, five published column layouts; provenance and per-vintage reconciliation in `tools/vintages/catalog.json`).
- **Population note:** the highway-only series is a deliberately different population from the Phase 0 all-records snapshot (e.g. 2025: 624,193 vs 743,398 rows). All FR-1.3 statistics describe **highway bridges as published in this series**.
- **Record filter — identical to the FR-1.2 trend job, so populations reconcile:** record type 1 only (the route *on* the structure); identity = state code + structure number; where that identity collides within a vintage, the row appearing **first in the published file is kept** (deterministic `SOURCE_ROW` tie-break, character for character `tools/trends/trends.sql` §1(b)), and the count is reported per year rather than hidden. 2,854 keys collide across 1992–2025 (954 in 1995, 2 in 2025), so the two jobs share a population of **20,649,259 structure-years over 1,039,109 structures**. *(v1.1 correction — v1.0 said such rows were "excluded entirely" while claiming in the same sentence to be identical to FR-1.2. Only keep-first actually reconciles; excluding entirely would cost 2,854 structure-years and make FR-1.3 disagree with FR-1.2's published figures.)*
- **Ratings used:** the four typed condition columns — item 58 (deck), 59 (superstructure), 60 (substructure), 62 (culvert). A value counts only when it is **exactly one digit after trimming**; anything else is null and never imputed — `N`, lowercase `n`, blank, and anything longer. This is `trends.sql`'s rule character for character (`regexp_matches(trim(x),'^[0-9]$')`), which is itself pinned to `ConditionClassifier.LowestRating`. *(v1.1 — v1.0's "`N`/blank" was not an exhaustive statement of the domain, and an implementation reading it literally as `IN ('N','')` would coerce the lowercase-`n` rows into ratings.)*

## 3. Pairing rule

A **transition observation** is one structure observed in two *consecutive* vintages:

1. Pairs are formed per structure identity for (year, year+1) only. A structure absent from either vintage contributes no pair for that year — **gaps are never bridged or interpolated** (16,641 structures have at least one gap year in the 2026-07-26 build).
2. Pairs are formed **per component**. A (deck) pair requires a non-null item-58 rating in *both* years; likewise for superstructure, substructure, and culvert. A structure can therefore contribute to some component families and not others in the same year-pair (most culvert records rate item 62 and code 58/59/60 as `N`, so they appear only in the culvert family — but **30,485 structure-years, 22,967 pair units, publish both** and contribute to both families; v1.1 corrects v1.0's "only … and vice versa", which is false by that margin). Nothing is deduplicated across families: the four matrices are **independent populations and must never be summed or combined into an "any component" matrix**.
3. Rating improvements (e.g. 4 → 8 after a rehabilitation) are **retained as observed**. This is a record of published history, not a decay model; censoring improvements would misstate that history. Item 106 (year reconstructed) is *not* used to segment pairs in v1 — a documented limitation (§6).

## 4. Matrices

**Basis (decision 2026-07-26): per-component.** Four matrix families — deck, superstructure, substructure, culvert. The governing (lowest-of-components) rating is *not* used as a matrix basis: a governing-rating change can occur merely because a different component became the minimum, which would conflate component switches with actual rating movement. (The FR-1.2 trends view remains governing-based; the two views answer different questions and each says which.)

For each cohort (§5) and component family:

- **Counts:** a 10×10 matrix `N[i][j]` = number of pairs whose rating moved from `i` (year y) to `j` (year y+1), i, j ∈ 0–9. **All 33 year-pairs 1992→1993 … 2024→2025 are pooled into one matrix** (v1 — the year-pair is not a matrix dimension; per-year-pair matrices put 63 of 1,320 national rows below the floor, minimum n = 2). Because pooling hides *when* the evidence was published, every row carries and displays its observed span: first and last from-year, and how many distinct year-pairs contributed.
- **Rates:** row-conditional frequencies `P[i][j] = N[i][j] / rowTotal(i)`, displayed as percentages to one decimal.
- **Any summary share is a rate too, and obeys the same floor.** The unchanged (diagonal) share quoted in the §6.1 caption is computed over the rows that clear the floor and no others; a matrix with no such row states no share at all. Computed across the whole matrix it would publish a percentage from evidence the same view just suppressed — and where a matrix has a single populated row that percentage *is* the `P[i][i]` the floor withheld. 395 of the 1,028 cohort matrices in the 2026-07-26 build are in that state.
- **Sample-size floor (decision 2026-07-26): n ≥ 50 per row.** The denominator of every rate is its row, so the floor applies per row: any row with `rowTotal(i) < 50` renders **"insufficient data"** for all its rates — never a number. Counts and row totals are always displayed regardless, so readers can judge the evidence for themselves. This is how FR-1.3 AC-3's "cells under a documented sample-size floor" is implemented: suppressing a whole row is strictly more conservative than a per-cell test, so no SRS change is needed. The floor value ships with the run rather than being hardcoded in the SQL, the API and the UI separately. Measured on the 2026-07-26 catalog: **3,227 of 6,273 cohort rows (51.4%) suppress their rates, covering 37,596 of 49,988,580 pairs (0.075%)** — half the rows go dark, a thousandth of the evidence does.
- A national all-cohorts matrix per component family is also computed as context, and it is the **exact sum of every cohort**, including the "Outside contiguous U.S." and "Not published" buckets. In the 2026-07-26 build every from-rating row of every national family clears the floor (smallest: culvert from-rating 1, n = 358) — but that is a fact about this build, **not a guarantee**: it is false at fixture scale (21 of 28 rows) and per-year-pair (63 of 1,320). The floor is applied to the national matrix by the same code path as every other matrix and is never bypassed, and no test asserts otherwise. *(v1.1 — v1.0's parenthetical "(it is always above floor)" invited exactly the bypass this now forbids.)*

## 5. Cohorts

Cohort = **structure type group × material group × climate region**.

- **Material groups** are defined here for the first time — no material grouping existed anywhere in the repo, only the flat item-43A decode (`NbiCodes.Materials`). They collapse that decode on the continuity distinction NBI itself draws, purely to reach viable cohort sample sizes: Concrete (codes 1–2), Steel (3–4), Prestressed concrete (5–6), Timber (7), Masonry (8), Other (0, 9). The decode stays authoritative for labelling an individual code. *"Other" holds code 0 (Other) and code 9 (Aluminum, wrought iron, or cast iron); because that name under-describes code 9, the implementation renders every group's member codes with their published decodes beside it rather than relying on the group label alone.* *(v1.1 — v1.0 said "reuse the Phase 0 decode lookups … must not invent new groupings" in the same breath as listing a grouping that did not exist; the intent, honoured here, is that the group **members** come from the published decode and nothing is invented about what a code means.)*
- **Type groups** are reused verbatim from the existing item-43B grouping the filter rail presents. It already existed twice — `web/src/state/filters.ts` (`TYPE_GROUPS`) and `src/SpanSight.Core/Ai/NlFilterSpec.cs` (`NlTypeGroups`) — held together only by a comment. FR-1.3's SQL is a third expression of the same rule, so the C# copies were collapsed into one (`NbiCohorts.TypeCodesByGroup`) and a golden test now executes the job's own assignment and asserts it agrees with the C# on every published code in both directions, plus C#/TypeScript parity.
- **Cohort attributes are read from year y** — the from-year, whose rating is the matrix row. 43A differs across a pair on 137,630 of 19,592,626 consecutive structure pairs (0.70%) and 43B on 136,398 (0.70%) — that denominator counts every consecutive pair, before the rated-component filter, so it is larger than the 19,537,768 the manifest publishes as `structurePairs` (pairs contributing at least one rated component); pairs are neither dropped nor double-counted when that happens, so the cohort matrices remain an exact partition of the national matrix. *(v1.1 — v1.0 did not say, and the choice changes published numbers.)*
- **Item 43A or 43B not published:** a labelled **"Not published"** bucket in that dimension — reported, never dropped, never folded into "Other" (7,316 component pairs have no 43A and 9,499 no 43B, with from-years 1992–2012; nothing after 2012). Folding them into "Other" would turn "FHWA published nothing" into a published material or type claim, which §2's "never imputed" forbids. *(v1.1 — v1.0 did not say.)*
- **Climate region:** the public NOAA/NCEI nine-region mapping of the 48 contiguous states, as a static lookup — no new data pipeline:

| Region | States |
|---|---|
| Northeast | CT, DE, MA, MD, ME, NH, NJ, NY, PA, RI, VT (+ DC, by convention) |
| Upper Midwest | IA, MI, MN, WI |
| Ohio Valley | IL, IN, KY, MO, OH, TN, WV |
| Southeast | AL, FL, GA, NC, SC, VA |
| Northern Rockies & Plains | MT, ND, NE, SD, WY |
| South | AR, KS, LA, MS, OK, TX |
| Southwest | AZ, CO, NM, UT |
| Northwest | ID, OR, WA |
| West | CA, NV |

- **Outside the contiguous U.S.**: implemented as the *else branch* of the nine-region map — any state code that resolves in `StateFips` but has no CONUS region — rather than as a fixed list, so a territory FHWA has not published yet cannot be silently dropped (American Samoa and the Northern Marianas have zero rows in all 34 vintages but exist in `StateFips`). A state code that resolves to **nothing at all fails the build** rather than landing in an unnamed bucket; zero such codes exist across the 34 vintages. Kept as a single labelled **"Outside contiguous U.S."** bucket — reported, never silently dropped, and flagged as climatically heterogeneous *and temporally inconsistent*: AK, HI and PR appear in all 34 vintages, Guam only 2018–2024 and the U.S. Virgin Islands only 2019–2025. Because the bucket is pooled with Alaska, Hawaii and Puerto Rico, their 332 and 299 pairs do land inside rows that clear the floor and publish rates — the row's span is the only signal that those jurisdictions were unpublished for most of the period, which is why it renders beside every n.

## 6. Known limitations — these ship with the numbers

1. **Inspection cadence inflates the diagonal.** Item 91 records a 24-month cycle on 83.79% of type-1 structure-years, and intermediate annual files carry the last inspection forward. The diagonal therefore dominates every matrix: **91.03% of deck pairs, 92.00% superstructure, 91.62% substructure and 93.12% culvert show no change** (91.69% overall). Segmenting deck pairs on item 90 shows the mechanism directly — 98.85% of pairs whose inspection date was carried forward are diagonal, against 84.40% of pairs whose inspection date changed. Off-diagonal rates therefore **understate** true annual change. This caveat, carrying the measured share of the matrix being displayed, must appear as a caption wherever matrices render; a "new inspection only" variant segmented on item 90 is future work (§6.5). *(v1.1 — stated numerically, since the file already contains the evidence and a vague caption is weaker than the data supports.)*
2. **The 10-year rule (early vintages).** The 10-year-rule status columns (`STATUS_WITH_10YR_RULE` / `STATUS_NO_10YR_RULE`) are present 1992–2009 **and again 2012–2018**, and absent in 2010–2011 and from 2019 — the layout sequence is not monotonic (`tools/vintages/catalog.json`, `absentColumns`). They record a cancelled FHWA deficiency policy. *(v1.1 — "1992-era" mislocated the boundary.)* It affects *status* columns only, **not** the raw ratings used here; but any narrative that compares deficiency status across that boundary is comparing two definitions. FR-1.2/FR-1.3 UI copy must not use "deficient" across eras without this note.
3. **Coding-practice drift.** Rating guidance and state recording practices evolved across 34 years and five file layouts; era provenance is in the catalog. Transitions near layout boundaries are published-data artifacts wherever the data says so — not adjusted.
4. **Identity churn, and it is not uniform.** Structure numbers can be recoded; a recoded structure ends one series and starts another, with no pair across the recode, and no re-linking is attempted in v1. The worst case is 1992→1993: Alabama recoded every structure number between those vintages (item 8 goes from 15 characters to 6), so **0 of 15,421** Alabama structures pair across that boundary, and Oklahoma is 0 of 22,888. Nationally 524,188 structures still appear in both vintages, yielding 521,700 structure pairs and 1,369,268 component pairs — so the loss is invisible in a total and visible only per state.
5. **Deferred to v2.** Improvements remain in the matrices as observed (§3.3); segmenting them by item 106 (year reconstructed) is future work, as is a "new inspection only" matrix variant segmented on item 90 (§6.1). Both are scope choices, not data limitations — the columns are in the normalized schema.
6. **Connecticut 2022:** Census replaced Connecticut's eight counties with nine planning regions in 2022, but **NBI item 3 still publishes the eight legacy codes 001–015 in every vintage through 2025** — verified over all 34. FR-1.3 has no county dimension, so it is unaffected either way; the discontinuity is confined to the NBI↔Census join (FR-1.5, `tools/census/README.md`). *(v1.1 — v1.0 implied a break in the NBI series itself. `tools/trends/trends.sql` and `tools/census/README.md` carry the same wrong claim and are corrected separately, outside this PR, to keep the diff coherent.)*
7. **Population framing:** highway bridges only (§2); figures will not match all-records publications.
8. **Some cohort cells are era artefacts, and say so.** A component can be rated on a structure whose type group does not suggest it, and that practice changed: 19,927 deck pairs sit inside the **Culvert** type group, 19,751 of them (99.1%) with a from-year of 2008 or earlier, and at published-row level from-ratings 5–9 still clear the n = 50 floor (from-ratings 3 and 4 do not: their largest rows are 18 and 49). The mirror case is 9,462 culvert-component pairs outside the Culvert type group — 9,207 in a published non-culvert group plus 255 whose 43B was not published. Such cells are **not suppressed**; that would violate "reported, never silently dropped". What mitigates them is the observed span on every row (§4). **The build's ≤5-year-pair diagnostic does not catch this case** — these rows draw on 7–32 year-pairs, so none of them appears in it — and the span alone is a weak signal here: the largest, Concrete × Northeast from-rating 7 (n = 263), displays "1992–2024, 32 vintage pairs" while 90% of its evidence predates 2009. A diagnostic keyed on the share of a row's pairs before a cut year is the honest fix and is v2 work; until then this limitation is the disclosure.

## 7. Presentation rules (FR-1.3 AC-4)

- Cohort-level views **only**. FR-1.2's per-structure sparkline reproduces that structure's own published ratings and is not a deterioration statistic; the distinction is named here because the two sit in the same product. No transition matrix, rate, or cohort comparison is ever rendered for a single structure, and no API route under `/api/deterioration` accepts or returns a structure identifier — asserted as a route-and-payload test, not left to convention.
- Sample sizes always visible; sub-floor rows render "insufficient data", never a rate — and no summary statistic (§4) may restate suppressed evidence as a percentage elsewhere on the page.
- The GR-6 disclaimer and a link to this document sit **adjacent to every matrix or rate**, plus the §6.1 cadence caption carrying that matrix's own measured unchanged share, and the row's observed span. The API supplies the method note, the methodology version and the link with every matrix response, so no view can render a matrix without them. The link target is `docs/METHODOLOGY-DETERIORATION.md` on GitHub; `docs/` is not deployed to the Static Web App, so naming the target here stops the implementation inventing one.
- Shading never implies a judgment the data does not carry: declines and improvements are tinted in different hues rather than one "changed" ramp, and the diagonal — which holds 91–93% of every real cohort — is kept off the off-diagonal colour scale entirely. Counts are visible in every cell regardless of shading.
- CSV/exports of matrices (if any) embed the method note and this document's version.

## 8. Reproduction & verification

- The job is offline DuckDB SQL (`tools/deterioration/deterioration.sql`) that expects one relation from its caller — `nbi_source`, the normalized vintage columns, every one named explicitly and never `SELECT *` — exactly as `tools/trends/trends.sql` does. `tools/deterioration/build-deterioration.sh` points it at the real Parquet set or at test fixtures, so CI golden-tests the same SQL that produces the published numbers. Every number stays reproducible from a clean checkout plus the Parquet set; `tools/vintages/catalog.sql` remains the entry point for reconciling the *inputs* (`nbi_reconciliation`: 34/34 reconcile) and the run stamps the catalog SHA that pins them. Outputs land as aggregates only (ADR-005) with the run's catalog SHA, job id, methodology version and sample-size floor stamped as provenance. *(v1.1 — routed literally through `catalog.sql`, which hardcodes the real Parquet path with no fixture switch, the job could not be run over fixtures at all and AC-3 would be unimplementable.)*
- **Invariants (enforced by the build and asserted as tests):** every pair is consecutive with both ratings 0–9; no pair falls into an unmapped region, material group or type group; row totals equal the cells beneath them; the cohort matrices sum to the national matrix cell by cell, including the "Outside contiguous U.S." and "Not published" buckets; the national sentinel is all-or-nothing; no published group is spelled with the reserved sentinel value; every row's span can describe its own pairs. The build refuses to write anything unless all seven hold, and each check returns the violating rows rather than a boolean.
- **The group assignments are held against the C# in both directions** — all 10 published item-43A codes, all 23 item-43B codes and all 56 state codes — because the rule now exists in the SQL, in `NbiCohorts` and in the SPA's filter rail. Mutation-verified.
- **AC-3 is verified on two fixtures, because one cannot do it.** A hand-written synthetic vintage file (`src/tests/fixtures/deterioration/`) is the job's input for the hand-computed matrix: it is the only way to reach a second climate region, the non-CONUS bucket, the "Other" material group, the "Not published" bucket, the record-type filter, the duplicate-key tie-break and a pair whose cohort attributes change mid-pair. Its README states every expected cell, and all 30 are asserted individually. The committed era fixtures then run the *published* SQL over real published rows for anti-drift: they contain exactly one consecutive-vintage pair (2016→2017 — 297 shared identities, 296 contributing structures, 662 component pairs: 183 deck / 183 superstructure / 183 substructure / 113 culvert), of which 7 of 28 national rows and exactly 1 of 89 cohort rows clear the floor — so both branches of the sub-floor rule are exercised on real data. Sub-floor rendering is asserted at both API and UI level.
